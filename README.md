# StageVote

Live voting for a programme of sequential rounds. Participants vote from their phones as
each round goes live; organisers run the programme from a live control dashboard.

- Participant app: invitation email with user ID (their email address) and password,
  countdown and sign-in, a programme lobby that updates itself, per-round ballots with a
  receipt for every vote. No self-service sign-up or password reset: organisers re-send
  invitations.
- Admin dashboard: programme settings, rounds and nominees, participant import and
  invitations, live control (open, close, start next, deadlines, schedule override),
  results with CSV export and publication, email delivery status, audit log.
- Safety: one vote per participant per ballot enforced by PostgreSQL, a precise voting
  cutoff, idempotent submissions with receipts, one active browser session per
  participant, durable email and schedule jobs, live updates across API processes.

Read [docs/architecture.md](docs/architecture.md) for how it works,
[docs/operations.md](docs/operations.md) for event-day operation,
[docs/email-setup.md](docs/email-setup.md) for SMTP and Google Workspace, and
[docs/verification.md](docs/verification.md) for what was tested and measured.

## Quick start (local)

Requirements: Docker with Compose v2, Python 3 (for the bootstrap script).

```sh
scripts/bootstrap.sh                     # creates .env with generated local secrets (idempotent)
docker compose up -d --build             # db, mailpit, migrate, api (2 processes), worker, web, proxy
docker compose run --rm migrate stagevote seed-demo --participants 40   # optional demo data
```

Bootstrap prints the URL. It prefers port 3000 and picks the next free port from 3100 when
3000 is busy; the chosen value is `STAGEVOTE_HTTP_PORT`/`APP_BASE_URL` in `.env`.

| What | URL |
|---|---|
| Participant app | `http://localhost:<port>/` |
| Admin dashboard | `http://localhost:<port>/admin` |
| Local test inbox (Mailpit) | http://localhost:8025 |
| API docs (development only) | `http://localhost:<port>/api/v1/docs` |

**Initial admin login**: the email and password are `ADMIN_BOOTSTRAP_EMAIL` and
`ADMIN_BOOTSTRAP_PASSWORD` in `.env` (generated by bootstrap). The `migrate` service creates
that admin only if it does not exist; rerunning never resets an existing admin's password.
To add an admin interactively: `docker compose run --rm migrate stagevote create-admin --email you@example.com`.

**Try the participant flow**: with the demo seed, open *Admin › Participants*, invite a
few `guestNNN@example.com` participants, open the invitation in Mailpit, sign in with the
email address and password it contains, then open a round from *Admin › Live control*. A sample import file is in
`scripts/sample-participants.csv` (synthetic addresses, including one invalid row and one
duplicate to show the import preview).

To test from phones on your network, set `STAGEVOTE_BIND=0.0.0.0` and
`APP_BASE_URL=http://<your-lan-ip>:<port>` in `.env`, then `docker compose up -d`.


## Commands

Backend (from `apps/api`, against the Compose database; `. ../../scripts/host-env.sh` first):

```sh
uv sync
uv run pytest -q                 # integration tests on real PostgreSQL (creates a temporary database)
uv run ruff check src tests && uv run mypy
uv run stagevote --help          # bootstrap, migrate, create-admin, worker, seed-demo, seed-loadtest, reconcile, check-privileges
```

Frontend (from `apps/web`):

```sh
npm ci
npx tsc --noEmit && npx eslint .
npm run build
```

Browser checks (isolated stack on port 3180, Mailpit API on 8085; Playwright runs in its
official container):

```sh
tests/e2e/run.sh                                  # all projects: Pixel 7 Chromium, iPhone 14 WebKit, desktop Chromium
tests/e2e/run.sh --project=mobile-chromium specs/journey.spec.ts
```

Load test (isolated stack on port 3190, synthetic accounts only):

```sh
tests/load/run.sh --yes-synthetic-load --voters 500 --rounds 3 --burst 10
```

Operations:

```sh
scripts/backup.sh                                  # database dump + media archive in backups/
scripts/restore.sh --yes-replace-database backups/stagevote-<stamp>.dump backups/media-<stamp>.tgz
docker compose run --rm migrate stagevote reconcile
```

## Development without rebuilding images

Run the API and Next.js on the host with hot reload, behind the same Caddy routing:

```sh
docker compose up -d db mailpit
. scripts/host-env.sh && export APP_BASE_URL=http://localhost:3101   # the API checks the browser's Origin
(cd apps/api && uv run stagevote bootstrap && uv run uvicorn stagevote.main:app --port 8711 --reload) &
(cd apps/api && uv run stagevote worker) &
(cd apps/web && npm run dev -- --port 3105) &
docker run --rm --network host -v "$PWD/infra/caddy:/etc/caddy:ro" -v "$PWD/media:/srv/media:ro" \
  -e SITE_ADDRESS=:3101 -e API_UPSTREAM=127.0.0.1:8711 -e WEB_UPSTREAM=127.0.0.1:3105 caddy:2.11.7-alpine
```

Open http://localhost:3101.

## Production

See [docs/operations.md](docs/operations.md). In short: real domain, `APP_ENV=production`,
HTTPS through Caddy (`compose.prod.yaml`), SMTP or Google Workspace email, no published
database or test inbox, backups.
